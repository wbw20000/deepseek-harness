# Agent Note: 冻结 macOS 候选运行时

Status: implemented

[English](2026-09-17-frozen-mac-launcher.md) | 中文

## 问题

当工作区或全局 Node 被移动或损坏时，源码链接启动器就会失效。单独试用的候选包需要不会被开发过程覆盖的可运行字节和数据。

## 决策

显式启用的冻结候选包自带已准备好的 dsh 依赖目录和独立 Node 的字节副本。它保留 Swift AppKit 生命周期管理者，通过受支持的 `dsh web` profile 启动。构建不安装依赖，不替换已有 App。原子的不可替换发布和独立冻结版 bundle 标识符将试用与已安装启动器区分开。

Resources 包含运行时、Node、启动配置补丁、配置文件和 SHA-256 清单。内部链接展开为文件，外部链接被拒绝；副本不能与源码输入共享可写 inode。原生文件先签名，再记录清单摘要。Swift 在启动 Node 前验证完整文件集合、大小、权限位、摘要和链接数。元数据只允许有大小上限的普通文件；校验在主 actor 之外执行且可取消。即使配置损坏，bundle 标识仍选择冻结模式，因此缺失元数据不能触发源码链接回退。

构建记录显式指定的全新数据目录，不复制用户数据。冻结版子进程同时将它用作 `DSH_HOME` 和工作目录；UNIX `HOME` 保持不变。这避免加载环境调用目录中的 `.env`，同时保留操作系统主目录语义。内置配置补丁选择由操作系统分配的回环端口。环境清理移除 Node/dyld 注入变量和疑似凭据名称；这不是权限隔离。

## 考虑过的替代方案

源码链接和硬链接无法在开发者改动目标时保留可运行字节。独立文件副本占用更多磁盘，但消除了这一依赖。在启动器中加入通用依赖解析器，会给启动引入网络和包安装失败路径；因此构建器接收单独准备并验证的依赖目录。

## 后果

清单检测意外损坏，不能防御有能力同时替换元数据与负载的恶意操作者。ad hoc 签名支持本地执行，不代表公证或人工发布批准。候选包拥有普通用户权限；存储配额、网络限制和无人值守迭代需要独立机制。显式启用的[恢复 App](../feature/2026-09-18-recovery-mac-apps.zh.md)提供独立恢复入口，而非上述隔离机制。构建成功或测试通过绝不授权升级。

## 既有决策

[源码链接启动器决策](2026-09-17-source-linked-mac-launcher.zh.md) 对默认模式、发布和进程所有权继续有效。冻结模式增加独立配置，并不取代该选项。[统一 dsh 启动器决策](2026-08-22-single-dsh-application-launcher.zh.md) 继续拥有 Node 入口的权威。没有符合归档条件的活动记录。

## 验证

[启动器检查](../../../../deliverables/mac-launcher/README.zh.md#tests) 覆盖无效元数据、字节与权限变化、链接拒绝、取消、陈旧完成结果、子进程环境、构建发布和副本独立于输入的行为。显式启用的冒烟测试通过 Swift 控制器运行实际内置后端，包括停止和重新打开。原生窗口与浏览器试用和无界面证据分开记录。在声称特定产物独立可运行前，脱离源码的运行时检查必须拒绝访问源码工作区和全局 Node，并用负对照确认这些拒绝确实生效。
