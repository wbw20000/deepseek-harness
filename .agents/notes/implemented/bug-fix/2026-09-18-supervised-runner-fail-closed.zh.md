# Agent Note: 有人监督的 runner 辅助函数失败即拒绝

Status: implemented

[English](2026-09-18-supervised-runner-fail-closed.md) | 中文

## 问题

直接子进程可能成功退出，但后代进程仍在写入、输出已被截断，或断言通过祖先目录的符号链接读取了实验之外的文件。将这些观察判为成功，会使后续任务结论不可靠。[任务控制基础](../../proposed/feature/2026-09-18-self-development-task-control-foundation.zh.md) 负责任务状态与批准预算；这些辅助函数负责进程及文件系统观察，不负责任务批准。

## 决策

有人监督的执行器在标准输出溢出时失败，并在首次停止触发时固定 SIGTERM 到 SIGKILL 的期限。首个会话事件固定所报告的身份。验收输出溢出会使所有断言失败。二者在管道关闭后都确认原 POSIX 进程组已经消失；出错或超过有限确认时长会拒绝本次运行。在启动进程前拒绝 Windows 执行。

验收定义的位置与文件路径通过文件系统解析；缺失根目录被拒绝，使用路径时再次检查。产物符号链接记录链接文本，不读取外部目标内容。在场证据持有经校验确认记录的副本。测试只取消并等待自身拥有的运行，不按夹具名称杀进程。

## 考虑过的替代方案

**直接子进程退出时就返回。** 这无法确认后代已停止修改工作区。辅助函数改为等待管道关闭并确认进程组退出，代价是额外但有限的等待，以及可能因未回收进程而拒绝运行。

**保留截断输出并信任保留下来的断言。** 缺失输出可能掩盖后续事件，不能支持完整运行的结论。即使已保留的前缀含有成功标记，溢出仍然失败即拒绝。

**将工作目录和环境变量允许清单视为隔离。** 二者都不会移除子进程的操作系统权限。有人监督的路线明确记录此限制，不声称可以保护无人值守执行。

## 后果

这些辅助函数阻止常见的意外越界并拒绝不完整观察，但不是独立监督者或沙箱。后代切换进程组、数字进程组 ID 复用、同用户并发替换文件、墙钟调整、宿主故障与休眠仍需更强的监督。它们不会启用自动任务循环、启动批准、证据流水线或安装升级。回归测试覆盖直接进程正常结束但后代仍存活、重复停止触发、输出溢出、祖先链接、缺失根目录，以及在场输入被修改。
