# Agent Note: 部署批准的额外可写根目录

Status: implemented

[English](2026-09-17-deployment-extra-writable-roots.md) | 中文

## 问题

部署可能需要写入第二个项目目录，但不应获得不受限的文件系统写权限。只为 shell 命令授权该目录会使文件系统工具无法执行同一任务；授权宽泛的父目录则会暴露无关项目。

## 决策

`sandbox-policy` 接受可选的绝对路径 `extraWritableRoots`，对执行环境中的路径写法去重，并在每次解析的策略中携带它们。本地强制执行提供方规范化路径；SSH 保留路径，直到远端主机执行权限检查。文件系统围栏、bwrap、Landlock 和 Seatbelt 仅在 `workspace-write` 下消费同一组配置根目录。空配置保持现有策略字段和模型可见文本不变。配置根目录出现在已记录的当前策略上下文中。

Windows ACL 执行器在创建授权或启动子进程前拒绝该组合。其确定性工作区 SID 授予持久访问权：将该身份用于额外目录，会使配置移除根目录后访问权仍然存在。现有工作区和私有临时目录生命周期保持不变。

## 考虑过的替代方案

**不受限模式或更宽泛的工作区父目录：** 两者都会授权无关写入。显式部署列表保留较窄的访问范围。

**持久的 Windows 额外目录 ACL：** 删除配置路径不会移除其持久权限。支持此功能需要单独验证可撤销的权限生命周期，而非仅增加执行器参数。

**各工具独立的允许列表：** shell 和文件系统操作会产生分歧。解析后的执行策略为两个消费方提供相同输入。

## 后果

该设置作用于整个部署，并非单任务授权或自开发隔离保证。它不限制读取、网络访问或进程控制。配置目录必须存在于执行环境中；不支持的后端组合会报错，而非静默扩大访问权。已运行的子进程保留原有沙箱配置；修改配置影响后续约束操作，不影响现有进程。

策略、根目录、文件系统、本地配置、ACL 拒绝和 SSH 测试覆盖各消费方。真实 Seatbelt 测试检查获准写入和相邻目录写入拒绝；`session-sandbox-extra-roots` 记录检查已记录的策略与文件系统结果。Windows 原生行为仍由 Windows CI 测试负责。
