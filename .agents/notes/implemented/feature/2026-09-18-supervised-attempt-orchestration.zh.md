# Agent Note: Supervised attempt orchestration

Status: implemented

[English](2026-09-18-supervised-attempt-orchestration.md) | 中文

## 问题

有人监督的 runner 已拥有各个部件——受信时钟、人工在场确认、headless 执行器、独立验收器、持久证据——但没有任何东西把它们组合成一次尝试。没有固定组合时，调用方可以在为另一次启动捕获的确认下开始开发，可以通过从开发已经改动的 worktree 重新计算启动输入来重试，或者接受一个在验收运行之后内容又被改动的结果。[任务控制基座](../../proposed/feature/2026-09-18-self-development-task-control-foundation.zh.md)拥有控制器及其每次尝试的证据约定；[辅助能力限制记录](../../implemented/bug-fix/2026-09-18-supervised-runner-fail-closed.zh.md)拥有每个部件如何 fail closed。本记录拥有部件之间如何组合。

## 决策

`runSupervisedAttempt` 按固定顺序组合一次有人监督的尝试——判定状态与 revision，把确认绑定到解析出的 worktree、计划摘要、验收定义与产物集，写入或校验启动记录，让核心提交 `attempt/started`，运行开发，取摘要 A，运行验收，取摘要 B，比对 A 与 B，写入持久证据，把结果交回核心校验并提交。三个决策支撑这一组合：

- **每次尝试显式传入自己的证据与时钟；不缓存人工确认。** 每次调用都携带为该启动捕获的确认，runner 为该次调用的 `startAttempt` 用它构造一个全新的 `HumanPresenceCapabilitySource`；请求的时钟观测启动记录与证据，核心不缓存任何证据来源，重放时也绝不重新读取所传入的实例。
- **启动记录把操作绑定到其启动输入；重试要么重放，要么拒绝。** 首次启动计算摘要并把 `<evidenceRoot>/tasks/<taskId>/launches/<operationId>.json` 写一次。用同一 operation id 重试时读回该记录，并精确比对 worktree、验收路径与定义摘要、计划摘要、产物路径集以及源码与产物摘要；任何分歧都抛出 `SELF_DEV_RUNNER_LAUNCH_MISMATCH`，把启动拒绝给人工，而不是重新推导。记录的 `expectedRevision` 记录启动期望的 revision，并被刻意排除在比对之外，因为失败尝试后的重试必然到达更高 revision，绑定重试操作的是核心自己的重放检查。
- **摘要 A/B 比对判定内容稳定性。** 摘要 A 命名开发之后的内容；摘要 B 命名验收之后的内容。比对不相等时本次运行失败，即使所有验收断言都通过；证据同时记录两组摘要和 `contentStable`，让后来的阅读者看到这次改动。

没有结果文件的证据只算诊断记录；写在其旁边的结果文件才是尝试已被判定的标志。

## 已考虑的替代方案

**把首个证据来源与时钟缓存在 runner 或控制器上。** 缓存的确认会让后来的尝试在没有任何人工为该启动给出监督确认的情况下启动，并掩盖到底是哪次观察授权了它。每次尝试注入让确认与携带它的请求同进同出，代价是调用方为每次尝试重新组装两者；重放操作直接返回已记录结果，不触碰传入的实例。

**每次重试都重新计算启动摘要。** 开发会改动 worktree，重新计算会把重试悄悄绑定到与被确认内容不同的内容上——这正是该记录要防住的漂移。记录只写一次，代价是每个操作一个持久文件，并把分歧变成一次响亮的人工决定，而不是悄悄改绑。

**只按用例名比对验收结果。** 用例名与断言名不能证明执行的测试就是被确认的那些；名字不变而验收定义或产物集被替换时照样通过。绑定计划摘要、验收定义字节摘要与产物路径集，才能让这种替换被检测出来。

## 后果

重放的重试付出一次记录读取与字段比对的代价，但绝不启动第二个执行器，因此重试启动不会把开发跑两遍。A/B 比对为每次尝试增加两次 worktree 摘要计算，并让验收阶段改动内容的运行失败，这正是想要的拒绝。证据与结果写入是持久的，但同用户可改写；本组合没有在辅助函数已有的拒绝之外增加任何隔离，辅助能力限制记录中 supervised-not-unattended 的限制仍然约束整条流水线。

## 验证

聚焦测试套件（`tests/attempt.spec.ts`）覆盖：先失败后通过的尝试且两者都有已判定证据、同一操作重放而不二次启动执行器、被停止的尝试以取消结算且其 fixture 进程组被拆除、验收期间 worktree 变动时拒绝通过、步数上限与阶段期限失败、验收期限先触发、绑定不同产物集的确认被拒绝、证据写入失败使该轮失败而不通过任务、revision 冲突在任何副作用之前拒绝，以及结果文件写入失败被记录而不改变已提交结果。
