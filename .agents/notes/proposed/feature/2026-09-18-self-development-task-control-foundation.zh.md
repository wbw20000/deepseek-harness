# Agent Note: 自开发任务控制基础

Status: proposed

[English](2026-09-18-self-development-task-control-foundation.md) | 中文

## 问题

已批准的自开发设计需要一个控制层：它绝不能把模型的话当成人工批准，绝不能让迟到或身份不符的测试报告把任务翻成通过，也绝不能在重启后丢失已消耗的预算。仓库目前没有任何组件拥有这个状态机。缺少它时，后续的工作进程、验收器或发布集成都必须各自发明生命周期，而且每一个都会被诱导去相信实验程序自报的成功。

## 提案

在现有 workflow 组中新增可选启用的 `packages/workflow/workflow-self-development`。每个任务一个串行化控制器，拥有生命周期 `draft → planning-authorized → awaiting-plan-confirmation → awaiting-development-approval → ready → attempting → awaiting-trial`，终态为 `stopped` 与 `handoff`。控制器在私有配置的控制目录中持久化带哈希链的 JSONL 日志和受保护检查点，每条记录先 fsync 再让调用方行动，并在运行任何请求的副作用之前持久提交 `attempt/started`，因此首次构建失败只消耗该轮一次。

本次增量落实的控制加固决策：

- **在任何持久追加之前先折叠校验。** 被拒绝的操作不会让日志改动一个字节；操作再也不能在请求被拒后毒化持久日志。日志追加或 fsync 失败会锁死控制器实例的拒绝状态并要求人工 handoff——持久化结果不可判定时，控制器绝不继续。
- **串行化区段在持久启动提交处结束。** 尝试副作用在操作队列之外运行，尝试未决时 `stop` 仍被接受；结算重新进入队列，保持尝试身份，已取消或已停止的尝试只能以失败尝试结算（`SELF_DEV_ATTEMPT_CANCELLED`）。普通 `AbortSignal` 是受信执行器的协作式取消，绝不是子进程监督；迟到的成功绝不记为通过，已消耗的轮数与时间从不退还。
- **幂等按方法区分且执行显式。** 摘要覆盖控制器方法加显式执行负载；副作用回调绝不是重放内容，重新打开会把重放结果标记为重放而非新鲜成功。折叠会校验计划确认与人工可见草稿内容完全一致，而不只是版本。
- **读取带证据地失败关闭。** 日志只对普通文件做有界读取（拒绝符号链接、FIFO、目录），校验完整持久事件模式、结尾换行、分段名与序号一致、非空日志缺检查点，并区分缺席与拒绝的 errno；写入重试短写并 fsync 新目录项。哈希链无法对抗能同时改写日志与检查点的攻击者，因此控制目录必须保持在实验可写范围之外。
- **预算超限有裁决；执行是监督者义务。** 控制器拒绝报告的阶段时长或步数超出批准界限，并在 `SupervisorObligations` 中记载宿主监督者义务。监督进程尚不存在，因此真实执行保持拒绝。
- **证据来源显式落盘。** 每条能力证据声明其产生方式（`machine` 或 `human-presence`），来源无效的证据项拒绝启动，持久的 `attempt/started` 记录携带聚合来源。`human-presence` 只证明有人在场，不构成无人值守隔离；日志 schema 版本升到 2，版本 1 的日志被拒并进入 handoff。

设计取舍及其放弃的内容：

- **受信时钟与能力证据按调用注入，绝不做配置项。** Node 时钟无法证明 macOS 休眠与重启记账，也不允许任何布尔值宣称隔离已通过。证据来源缺失即拒绝启动；在 Swift 监督者、存储配额、沙箱覆盖和外部验收器出现之前，真实执行器集成保持关闭。
- **幂等键可跨越崩溃。** 已提交操作把负载摘要存入日志，重试操作重放已记录结果而不重复副作用；同一键携带不同负载会被拒绝。
- **损坏时拒绝而不是修复。** 畸形尾部、断链或检查点不匹配进入 handoff 并保留原始字节；不存在自动续作路径。哈希链不承诺抵抗宿主管理员，README 明确说明这一点。
- **不存在升级 API。** 试用批准绑定身份，并被后续变化失效；消费者只读取，不激活。

本包不注册工具、提示、事件或守护进程，也不进入任何默认 bundle。本包不削弱或扩展部署级 extra-writable-roots 沙箱设置，该设置明确不提供自开发隔离（[记录](../../implemented/feature/2026-09-17-deployment-extra-writable-roots.zh.md)）。延期工作记录在其 README 中：真实工作进程与验收器集成，以及按阶段与步数上限的宿主监督者执行。

## 考虑过的替代方案

- **把生命周期并入现有 workflow 引擎或 agent loop** —— 被拒绝：`ctx.workflowEngine` 拥有的是模型编写的编排脚本，agent loop 拥有的是回合执行；两者都不拥有批准、预算或按任务的持久日志。把任务控制耦合到其中任何一个，都会把批准语义摊到两条接缝上，并让后续的监督者、验收器和发布消费者依赖引擎内部结构。
- **在没有冻结计划摘要的情况下信任实验自报的测试结果** —— 被拒绝：本设计的核心威胁恰恰是自开发变更控制着谁报告成功。冻结计划并把结果、尝试与批准绑定到其摘要，才让迟到或被替换的报告可被识破；跳过它会把控制器降级为记账。
- **把受信时钟与能力证据做成 `cordis.yml` 配置项** —— 被拒绝：配置项可能被设错，也可能在上一次实验后忘着没关，而 Node 时钟无法证明 macOS 的休眠与重启记账。按调用注入把观察来源留在真正能观察它的组件手里，证据缺失即失败关闭。
- **修复或续作未通过校验的日志** —— 被拒绝：任何修复路径都是正在开发中的任务可能引导的代码。拒绝并交给人处理 handoff，把控制面留在实验够不到的地方，代价是人工处置。

## 验收标准

- 本包作为 workflow 组的可选成员存在，README 记载生命周期、配置、控制器操作、验证规则、日志保证与限制；不进入任何默认 bundle，不挂载进任何随发布配置。
- 聚焦套件证明每一项列名行为：预算验证与先到先停、批准顺序、失败前先消耗轮数、迟到/身份不符/超限报告拒绝、幂等重放与负载不匹配、先折叠后追加且被拒后日志逐字节不变、尝试未决时接受 stop 并拒绝其迟到成功、中断尝试重启与跨启动时间冻结，以及基于真实文件的畸形/截断/改写日志拒绝。
- dsh/Loader 组合冒烟从测试专用 `cordis.yml` 启动服务、驱动一个生命周期并释放。
- 未挂载生产监督者、工作进程、验收器或 Swift 时钟。测试专用证据来源只验证控制流程，不构成生产隔离证明。

## 风险

- **尝试运行期间的执行缺口** —— 控制器事后验证报告，但按截止时间终止、限制步数、确认子进程静默需要一个尚不存在的宿主监督者；在它落地之前，真实执行必须保持拒绝，而今天提供副作用的消费者自行接受这些义务（`SupervisorObligations`）。
- **日志的防篡改证明止步于宿主边界** —— 能同时改写日志与检查点的管理员或攻击者可以击穿它；控制目录必须保持在实验可写范围之外，而部署级 extra-writable-roots 设置明确不提供这一点。
- **人工 handoff 是唯一恢复路径** —— 被拒绝的日志会阻塞任务直到人工处置；无法为此配备人力的部署不应启用本包。
- **后续增量可能重塑公开类型** —— `CapabilitySource`、`TrustedClock` 与控制器 API 均为 pre-stable，预期随真实监督者落地而变化；早期消费者接受变动。
